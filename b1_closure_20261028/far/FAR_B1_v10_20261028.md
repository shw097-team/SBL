## 建議執行方案（分四波，波間可停）

**W-A 取基準（0 風險）**：各 repo `git fetch origin`；記錄 origin/main 尖端 sha；HG-KSEOS 用 PAT wrapper。

**W-B 產生證據包（0 風險）**：每 repo 建 `b1_closure_20261028/`：
- `MANIFEST.json`：每檔 path／bytes／sha256／provenance（哪個 gate、哪個 receipt）
- `EVIDENCE_INDEX.md`：問題 → 檔案#line → 可重跑指令
- 內容（小）：`GATES.json`、`NATIVE_ADMISSION_RECEIPT.json`、`CORPUS_NATIVE_RECEIPT.json`、`corpus_native_journal.jsonl`（精簡）、`OWNER_RULING_v1.json`、`DECLARATION_v1.json`、FAR v5～v10、`repo_state.json`／`candidate_screen.json`、探針輸出
- 代碼差異（HG-KSEOS／PIPD 各自放）：`native_admission.py` 的 D-16 修、`generic_route_runner.py` 的 D-8 修、`gates.py` 的 v7/v9 修、`wave1/`／`wave2/` 腳本

**W-C 守門與推送**：D6 掃描 → commit（`b1 closure 2026-10-28`）→ push 到分支 → 開 PR；逐 repo 以 `ls-remote` 驗證遠端尖端 == 本地，並回報 PR 編號／檔案數／manifest sha256。
