# FAR-B1 v8 — 覆蓋率、D-8、TTL、SourceFreeze（2026-10-28）

裁決順位：① 對齊 PKG_00～08 → ② Native E2E 閉環 → ③ 無人值守高自動化 → ④ 高必要性 → ⑤ 不過度治理 → ⑥ 低阻力高效率。

## M1｜18 條路由是文件推導的，不是自製腳手架

`grep` PKG_00～08 附件，18 個 route 名**全部**出現（1–5 個檔案）：
`immutable_evidence 3, repo_diff 2, native_continuation 3, source_oracle 3, repo_context_probe 3,
ecp_selection 3, sp_host_load 3, sbl_todo 5, no_fit 3, trace_closure 3, baseline_denominator 3,
hgk_native_golden 3, sbl_user_golden 3, bounded_coding 2, triple_golden_join 3,
golden_fabric 1, golden_hgk 1, golden_sbl 1`

→ 所以「30/30 無文件依據」這句話只在「數字」層面成立；**逐條 route 都有文件依據**。FAR v5 D1 的「不做」因此要修正。

## M3｜D-8 的謊報是子字串比對，不是路由缺失

`generic_route_runner.py:33-38`：

```python
def resolve(route):
    tail = route.split("::")[-1].lower()
    for hint, key in ROUTE_HINTS.items():
        if hint in tail: return key, IMPLEMENTED[key]
```

`native_issuer`（已有真 runner）被 `issuer` 命中 → 回 `ISSUER_SUBJECT`。這是**證據品質缺陷**，不是覆蓋率問題。

## M4｜TTL 1 小時不是文件要求

`grep 3600|max_ttl` PKG_00～08：0 命中（唯一命中的 L3304 是無關字串）。
門檻在 `native-trust-maintenance.ps1:151`（`-gt 3600 → throw ERR_EXACT_OWNER_SCOPE_REQUIRED`），
kernel 以 `registry['max_ttl_seconds']` 對 `expires_at - issued_at` 做檢查（`native_admission.py:317`）。

## 裁決

| # | 裁決 | 理由（順位） |
|---|---|---|
| D1 | 覆蓋率改為**三態**：`EFFECT_IMPLEMENTED` / `PRECONDITION_GATED`（附缺失輸入的實測探針）/ `NOT_IMPLEMENTED`。實作 10 條真實作，8 條轉為前置條件型拒絕 | ①（有文件依據）＋⑤（不造假 fixtures／不假裝選 ECP） |
| D2 | 修 D-8：`resolve()` 改**精確表**，未知路由回 typed refusal 並附路由全名 | ④⑥：證據品質，成本 0 簽章以外的行為改變 |
| D3 | TTL 上限 3600 → 43200（12h），保留 kernel 端 `expires_at` 強制與 registry pin | ③（無人值守）＋①（無文件衝突）＋⑤（不做 DPAPI escrow、不加第二控制面） |
| D4 | SourceFreeze 採 **(a) 凍結不改正本**：對 DOC-00 清單逐檔驗 sha256，產 `SOURCEFREEZE_MANIFEST.json` 由 owner 簽 | ①（不動上游 bytes）＋⑥（1 簽章） |
| D5 | 上述 registry 變更以**一次 console** 重簽（30 rows + root），合併 D4 的簽章 → **1 UAC + 1 解鎖** | ⑥ |

## 簽章與動作帳

| 動作 | 簽章 | 解鎖 | 提權 |
|---|---|---|---|
| 10 支 runner + D-8 + 三態覆蓋 | 30 + 1 root | 1 | 1（裝 registry） |
| SourceFreeze manifest | 1 | 併入同上 | 0 |
| **合計** | **32** | **1** | **1** |

## 明確不做

- 不建 golden fixtures、不偽造 ECP、不假裝 host 載入（③ 的自動化必須誠實失敗，不是假通過）
- 不動 `signed_payload()`，不改 `native_admission.py` 的驗證語義
- 不加 DPAPI escrow、不加第二控制平面
