## 一、問題：既然 PKG_00～08 沒有 30/30 要求，「12/30」從何而來？

**它有三個來源，逐層量測如下。**

### L1｜分母 30 = `runner-registry.json` 自己的列數

```
route_count 30 | rows 30 | status {INSTALLED: 30}
coverage {EFFECT_IMPLEMENTED: 12, NOT_IMPLEMENTED_EFFECT_TYPED_REFUSAL: 18}
route_id: OWNER_REGISTERED::<name>（root_probe, issuer_subject, …, golden_sbl）
```

PKG_06 有 **949 個 `R15-nnn` id、15 個 effect family**，與這 30 個名稱**交集 0**。
→ 「30」不是上游目錄長度，是某次 session 寫進 registry 的 runner 列數。

### L2｜唯一有文字的門檻要求的是 INSTALLED，而且已達成

`FAR11_HOLD_RULINGS.md:16` 引 OpenSpec `b1-native-lane-admission/tasks.md` L19：

> 每條路由至少 `INSTALLED`，才可宣稱 `EXECUTION_ADMITTED`

實測 **30/30 `INSTALLED`** → 這條**已滿足**。
「12/30 `EFFECT_IMPLEMENTED`」是比 L19 更嚴的自訂指標，**沒有任何條文要求它到 30**。

### L3｜18 個名字確有文件依據，但「必須全部有 effect」沒有

我複驗 v8 的 M1：18 個 typed-refusal 名稱**全部**在 PKG_00～08 出現（1–5 個檔案）。
但再量一層——搜尋「全部／皆／所有 … route … 實作／EFFECT」句式的命中數：

```
names with >=1 doc hit : 18 / 18     ← 名字有依據（v8 正確）
requirement-like hits  : 0           ← 沒有任何句子要求逐條 effect 實作
```

→ 名字是文件推導的；**「全部 30 條都要有獨立 effect」是本地推論，不是條文**。
且 v8 的 M2 已量到其中 8 條的輸入不存在（ECP 未執行、host 未載入、golden fixtures 無檔），
硬做只能是造假。

## 三、問題：`formal_sourcefreeze: HOLD` 誰能補？

量測：`input_20261027` 九冊 front matter 9/9 `formal_sourcefreeze: HOLD`；
`DOC-00 L327–330` 標上游來源 `READABLE_USER_INPUT;NOT_FORMAL_SOURCEFREEZE`。

來源在 `SBL` 知識庫，**只有上游 owner（你）能凍結**。兩條路：

- **(a) 凍結不改正本**：逐檔 sha256 manifest + owner 簽章 + `SOURCEFREEZE.json`；來源 bytes 不動 → **1 解鎖／1 簽章／0 bytes**
- **(b) 凍結並改正本**：front matter 改 `FROZEN` → bytes 變 → 所有引用 sha 的審計與 crosswalk 需重跑

建議 (a)。且它**不應成為 mission gate**：PKG 自己宣告 HOLD，驗收不因上游未凍結而不成立。

## 四、問題：D-8 與 TTL 為何先前不修／不改？
