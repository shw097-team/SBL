## 量測 1：兩條都不是量測出來的，是寫死的字串

`gates.py:232-234`：

```python
rs.append("SAME_OS_PRINCIPAL: issuer/checker/acceptance key material lives under one OS user; "
          "no second principal (DOC-13 L2775)")
rs.append("SOURCEFREEZE_HOLD / RELEASE_NOT_RUN: no Owner signature over the frozen bytes")
```

這與同一個函式的 docstring（「Residual blockers MEASURED at gate time, never a static list」）直接矛盾：
**即使把問題修好，這兩條也不會消失；它們也不是證據。**

## 量測 3：kernel 真正要求的 principal 分離已滿足

```
owner ...-1000  checker ...-1006  maker ...-1007   distinct = True
keys = ['OWNER-B1-d42c654cd1afba80']  purposes = [source_freeze, task_kind, oracle_ratification]
```

registry 只有一把 key（owner）→ **「每個 principal 各持金鑰」目前不成立，但沒有任何已讀條文把它列為載入前置**。

## 量測 4：SOURCEFREEZE 是「套件自己的宣告」，不是「缺一個簽章」

`input_20261027/FHS_MSC_B1_PIPD_LS_PKG_00…08` 全部 front matter：

```
formal_sourcefreeze: HOLD      ← 9 冊皆是
```

且 `DOC-00 L327–330` 把上游九冊標為 `READABLE_USER_INPUT;NOT_FORMAL_SOURCEFREEZE`。

→ 所以「沒有 owner 對凍結位元組的簽章」的根因是**來源從未被上游正式凍結**，不是我們漏簽一張紙。
用 `source_freeze` reference 去補，只會得到一張「對未凍結來源的簽章」，反而製造假象。

## 建議執行方案（全部 0 owner 動作）

1. `gates.py` 把兩條字串換成：

```python
# PRINCIPAL_SEPARATION（量測）
sids = {owner, checker, maker} from the installed native registry
declared.append({id: "PRINCIPAL_SEPARATION_MEASURED",
                 value: "3/3 distinct SIDs; key material: owner only (1/3 principals)",
                 satisfied: "sids_distinct",
                 open: "per_principal_keys",
                 owner_ruling_required: true, blocks_mission_completion: true})

# SOURCEFREEZE（量測）
hold = count of formal_sourcefreeze: HOLD in PKG_00..08 front matter (measured = 9)
declared.append({id: "SOURCEFREEZE_DECLARED_HOLD",
                 value: f"{hold}/9 冊宣告 HOLD；DOC-00 L327-330 NOT_FORMAL_SOURCEFREEZE",
                 not_fixable_by: "minting a source_freeze reference",
                 owner_ruling_required: true, blocks_mission_completion: true})
```

2. `mission_complete` 仍為 `false`，`why_not_complete` 顯示「2 declared ceilings awaiting owner ruling」，
   而不是兩條無法消散的字串。
3. 交付 owner 兩行裁決選項（可延後，不阻塞任何已完成的證據）。

## 殘餘風險

- 把 blocker 降級為 declaration 會讓 `mission_complete` 的語意從「無 blocker」變成「無 blocker 且無待裁決宣告」；
  這是我新增的**更嚴**條件，不是放寬。
- 若 owner 裁定 per-principal key material 必須存在，D2 的成本是 2 次解鎖 + registry 重簽（可批次）。
- 本 FAR 不動 `native_admission.py` 的 `PRINCIPAL_SEPARATION`（那條是真的量測且已通過）。
