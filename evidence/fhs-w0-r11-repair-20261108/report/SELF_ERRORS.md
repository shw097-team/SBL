# 本回合自我錯誤（r11）

> 只記真的發生過的。格式：做了什麼 / 代價 / 抓到它的東西 / 下次的規則。

## E-S12｜我手寫了一份會過時的整合交付

**做了什麼**：r10 的《整合交付》是我一個字一個字寫的（`out/FHS_W0_R10_CONSOLIDATED_FOR_EXTERNAL_ACCEPTOR.md`），裡面有
`567,669 B` 與 `b75057f7…`。之後文件為了修 `R1` 重產成 `568,120 B` / `2285baaf…`，整合交付沒有跟著重建。

**代價**：同一個 PR 裡出現兩個「主體身份」，而其中一個是錯的。外部驗收官（`EC-R10-001`）必須自己去推論哪個才是現行版——
這正是我這一輪在修的病的鏡像：**文件說了它沒量的事**。

**抓到它的東西**：車道的 stale-locator 掃描。它掃出 **10 個 STALE**，跨 4 個檔——不是只有那一個。

**規則**：**任何聲稱檔案 bytes/digest 的文件，都必須由 builder 從磁碟插值產生。** 手寫的數字不是文件，是筆記；
筆記可以過時，證據不行。

## E-S13｜修好的檢查，本身還要有一條否證條件

**做了什麼**：r10 把 `G18` 從 `startswith` 改成 `realpath` containment，把 `G16b` 從「誠實回報就給過」拆成 truthful/closed。
我以為那是修完了。

**代價**：兩支檢查各有第二條假綠路徑沒被封：
- `G18` 用 `doc.get("files", [])`，於是 `files: []` 或缺鍵 → `0/0` → **PASS**；
- `G16b` 對 `scan_complete=false` 的 subject，沒掃到的模組不會出現在缺集合 → **PASS**；
- 宣告集合把 `optional-dependencies` union 進來，於是補一個 `[yaml]` extra 就 `covers=true`，而 `pip install .` 不裝它。

**抓到它的東西**：外部驗收（`EC-R10-002/003/004`），以及車道直接 import 本回合的閘重現三項（`reproduced` 全為 true，另附正負對照）。

**規則**：**「這個檢查會不會在沒有證據時通過」要當成檢查的一部分來測**，不能只測「有缺陷時它會不會紅」。
前者叫假綠，後者叫假紅；假紅會被發現，假綠不會。

## E-S14｜`yaml` 我寫成 fail-open，那是錯的

**做了什麼**：r10 的車道工件寫 `yaml ... fail-open 設計`，我把那句話沿用進報告的敘事。

**代價**：一個**大聲拒絕**的行為被描述成**靜默放行**。前者是「這個功能不可用」，後者是「安全性被繞過」——嚴重程度差一個量級。

**抓到它的東西**：`EC-R10-005`，以及我自己回頭讀 `lane_policy.py` 的 `load_site`：PyYAML 不在時 `_yaml_load_unique` 回 `None`，
接著退回 `_json_load_unique`，重鍵丟 `ValueError`、非 JSON 丟 `JSONDecodeError`。**沒有任何一條路是靜默接受。**

**規則**：**「fallback 存在」不等於「fail-open」。** 要說 fail-open，必須指出一條會被 ACCEPT 的輸入；
指不出來就說「該功能 NOT_QUALIFIED」。

## E-S15｜我以為「三個豁免」，實際是 12 FIRED + 2 EXEMPT + 1 BASELINE_RED

**做了什麼**：r10 的交接寫「3 個具名豁免（G21、G22、G16b）」。

**代價**：`SELFTEST_EXEMPT` 字典裡確實有 `G16b`，但它在 baseline-red 分支就返回了，**根本沒走到豁免路徑**。
所以文件描述了一條程式沒有執行的分支——與 E-S14 同型：**描述了一個沒發生的行為**。

**抓到它的東西**：`EC-R10-006`，以及逐列讀 `GATE_R10_SELFTEST.json`。

**規則**：**豁免清單要從執行結果導出，不是從設定字典導出。** 設定說「可以豁免」與這次執行「真的豁免了」是兩件事。

## E-S16｜「CI 綠」我一直知道它不等於閘綠，但我沒去補

**做了什麼**：r10 交了 4/4 綠的 SBL PR，並在報告裡寫「CI 4/4」。我自己在 `G20` 那裡還特地把它降級成 lint，
卻沒有讓 CI 真的呼叫 `gate_r10.py`。

**代價**：一個讀者可以合理地以為綠燈代表閘跑過。`EC-R10-007` 指出四個 job 一個都沒呼叫它。

**抓到它的東西**：外部驗收直接讀 `.github/workflows/ci.yml`。

**規則**：**如果某個檢查很重要，就讓 CI 跑它；否則不要用 CI 的顏色暗示它。**

## E-S17（延續 E-S01 的形狀）｜我又一次在沒有分母的地方得到「通過」

**做了什麼**：`build_r11.py` 第一次跑時，`G16c` 因為 artifact 不存在而回 `ARTIFACT_ABSENT`；
但同一支 gate 對 `G18` 回的是 `NO_PAYLOAD`——兩者都是「沒有東西可檢查」。
如果我把 `NO_PAYLOAD` 寫成「沒有 payload，所以跳過」，那就是第二次 `0/0`。

**處置**：兩者都維持 **FAIL**（`ARTIFACT_ABSENT` 是 blocking、`NO_PAYLOAD` 是 blocking）。
空回合、空 manifest、空集合，一律不是通過。

**規則**：**「沒有東西可檢查」與「檢查通過」永遠是兩個判決。**
