# 本回合自我錯誤（r10）

> 只記真的發生過的。每一條寫「我做了什麼 / 代價 / 抓到它的東西 / 下次的規則」。

## E-S01｜我在修 `G13` 的同一個檔案裡，自己造了一個 `0/0` 的假通過

**做了什麼**：`build_r10_artifacts.py` 第一版把 external scope 的 class 寫成 `SOURCE_31`，但 lane D 在
`names_normalised` 裡用的 class 是 `NORMALISED_ONLY`。於是 `rows` 為空 → 分母 0、分子 0 →
artifact 寫出 `"source_files_with_at_least_one_divergent_copy": 0`，而這個 0 看起來像「沒有碰撞」。

**代價**：如果我沒加檢查，r10 會用一個**比 r9 更寬的 root 掃描**去證明「17 變成 0」，也就是用空白證據
撤銷一個真缺陷。

**抓到它的東西**：G13 新增的「分母必須等於 31、覆蓋必須等於分母、副本數不得少於名稱數」三條。
修正後為 0/31 與 17/31（348 份副本）。

**規則**：**任何計數都必須同時斷言分母**。分子可以為 0，分母不能。

## E-S02｜車道的靜態抽取看起來比突變更有說服力，而它錯得更多

**做了什麼**：`lanes/A/GATE_FORENSICS.json` 報「10 項中 5 項讀到 artifact 不存在的鍵」（我第一次讀到 7 項，因為車道後來又覆寫了那個檔——**引用一個會被覆寫的檔案時，必須連版本一起引**）。
我幾乎照抄進報告。

**代價**：那 7 項裡有 6 項的**真實欄位突變都 `FIRED`**——它們是活的。只有 `G13` 突變後仍 `PASS`。
若照抄，我會用一個誤報去掩蓋唯一真正的死斷言。

**抓到它的東西**：把 `summary.checks_with_missing_keys` 與 `mutations[].fired` 兩欄並讀。

**規則**：**突變是證據，靜態抽取是假設**。兩者不一致時以突變為準，並在報告裡寫出不一致本身。

## E-S03｜改 selftest 時把 `hygiene()` 整段刪掉

**做了什麼**：用字串切片替換 `MUTATIONS` 到 `def main()` 之間的內容，而 `hygiene()` 正好在那一段。

**代價**：`NameError: name 'hygiene' is not defined`。若我只看 selftest 的輸出（它不呼叫 hygiene），
這個洞會一直到推 PR 前的第一次完整 gate 才炸。

**抓到它的東西**：`python tools/gate_r10.py --round .`（完整模式）當場 `NameError`。

**規則**：**改完檢查器，跑完整模式，不要只跑 `--selftest`**。

---

## E-S04｜`G10` 第一版假設「文件自己的 header 在檔案開頭」

**做了什麼**：append-only 文件的 header 在**結尾**（r10 ＝ r9 的 552,605 bytes ＋ 本章）。第一版讀
`text[:4000]`，於是回 `PARENT_CLAIM_ABSENT`。

**代價**：一個正確的文件被判成沒有宣告。

**抓到它的東西**：gate 自己的輸出。

**規則**：append-only 文件的「自己的宣告」是**最後一個**，不是第一個——這正是 r9 的閘被騙的原因；
兩者其實是同一個事實的兩面。

---

## E-S05｜`G22` 會遞迴叫自己，跑到 180 秒超時

**做了什麼**：`G22` 用 subprocess 跑 `--selftest` 取得真實退出碼；而 `--selftest` 又會執行 `G22`。

**代價**：`exit 124`，一整個回合的閘跑不完。

**抓到它的東西**：指令超時。

**規則**：**檢查器不得以同一入口自我呼叫**；用 depth 環境變數在子行程跳過自己。

---

## E-S06｜交接第一版沒把 bytes 寫在檔名旁邊，`G21` 抓不到

**做了什麼**：把 bytes 放在表格的下一列。`G21` 的契約是「檔名後 160 字內必須有 byte 數」，
於是回 `CLAIM_NOT_FOUND`。

**代價**：不是文件錯，是**契約讓宣稱無法被檢查**。這比文件錯更該修：一份不能自動核對的交接，
下一個人只能靠信任。

**抓到它的東西**：`G21`。

**規則**：**宣稱必須寫成可被機器定位的形式**，否則等於沒有宣稱。

---

## E-S07｜把 69.5 MB 的 tarball 留在回合目錄裡

**做了什麼**：lane B 為了取 GitHub main 的三份檔案，下載了整個 tree 的 `main_src.tar.gz` 並留在
`lanes/B/raw/`。

**代價**：`hygiene` 判 `OVERSIZE`（上限 2 MB），閘 `FAIL`。

**抓到它的東西**：`hygiene()`。

**規則**：**取證可以下載大檔，回合目錄不行**；取完即刪，只留 digest 與抽出的檔案。

---

## E-S08｜差點把一次「紅的」閘結果當證據打包出去

**做了什麼**：payload 裡的 `GATE_R10.json` 是在 `hygiene=1` 那次執行後產生的，之後我只跑了
`--json out/GATE_R10_FINAL.json`。

**代價**：若不重跑，SBL 上的證據會顯示 `VERDICT FAIL`，而報告說 PASS——正是我這輪在修的病的鏡像。

**抓到它的東西**：把 staged 與 final 的 `summary` 逐欄比對（`same verdict: True`）。

**規則**：**打包的閘結果必須與最終閘結果逐欄相同**，不是「同一天跑的」。

---

## E-S09｜我把「斜線解析器」實作成整行切分，得到 0

**做了什麼**：`naive_slash_split_recount` 第一版對整行 `count("/")`，而每列結尾都有「更正/驗原 Raw」，
於是每列都被丟棄 → `0`。

**代價**：一個 `0` 看起來像量測結果，實際是我的實作錯。這與 r9 的 `G13` 是同一種失敗：
**錯誤的程式產生一個看起來合理的數字**。

**抓到它的東西**：與 `naive=10`、`robust=11` 對不上（`0` 不可能同時滿足兩者）。

**規則**：**數字對不上既有量測時，先懷疑自己的實作**（r10 報告的 `E-A01` 也教過同一件事）。

## E-S11｜我公布了一個自己算錯的 `R1`，而且是車道的獨立實作抓到的

**做了什麼**：`R1`（每個 fence 整體一塊、每個 table 整體一塊）第一版寫 **24,247**，並寫進 r10 正文、
報告、整合 MD 與 SBL payload。

**根因**：我的分類器把 fence **內的空白行**判成 `blank`，於是一個 fenced region 被切成好幾塊。
把 fence 內所有行（含空白）都算進同一個 region 之後得 **22,669**。

**代價**：一個「規則敏感度」的表格，裡面有一格是自己算錯的。這一節的全部論點是「數字必須連規則一起引用」，
而我引用了一個連自己的規則都沒實作對的數字。

**抓到它的東西**：車道 C 的獨立實作給 **22,672**。差異 3 塊讓我回頭查自己的分類器，而不是去改車道的數。

**處置**：兩個都公布——本工具 22,669、車道 C 22,672，差 3 塊（未閉合 fence、`~~~` 與 ``` 邊界）。
原本的 24,247 保留在產物裡標為 `earlier_value_defect`，不刪。

**規則**：**當兩個獨立實作差一點點時，那一點點就是規則沒釘死的地方**。把它抹平成一個數字，
就是把「規則未公布」換成「規則假裝已公布」——比原本的缺陷更難查。
